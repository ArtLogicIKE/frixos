When we wrote up v70 we called it a proper geek's update: signed OTA, a graphing engine, a brand-new filesystem. Since then, v71 and v72 went out quietly, and now Frixos reaches v73 (shown as version 2.80 on the System tab). This article covers everything from v70 to v73.

There are new features, and we'll get to them. But if you only read one paragraph, make it this one: most of the work in these three releases went into making the clock you already own more dependable. Better doesn't just mean more. A clock on your wall has one job above all others, which is to keep working without you thinking about it. So we spent these months hunting down every way it could stutter, freeze, drop a connection or run short of memory, and we fixed them one by one.

A big share of that work comes from the community. Benoit Poirier, the man behind the v67 graphing engine, sent five pull requests in this period, and his memory work is the backbone of v73. Details below, and a proper thank-you at the end.

The overview

Here are the headlines from v70 to v73:

  • More memory to spare. On our own test clock (Home Assistant and FreeStyle Libre both active), the lowest point of free memory went from about 14 KB on v72 to 35–45 KB on v73, with the same settings.
  • Connections that hold up. Secure connections to Home Assistant, your CGM, the weather service and the update server now queue up, check memory before they start, and recover from network hiccups instead of getting stuck.
  • A calmer boot. After a restart, the clock finishes its first round of fetches before it opens its web page, and the web page waits a minute before reconnecting.
  • Bugs you could see, fixed. A clock that froze when the light sensor switched between day and night brightness, Home Assistant values that blanked after a layout save, a last digit that went missing, and a scrolling line that hitched.
  • A friendlier layout editor. The palette shows what's on your screen, an Add Item tile adds the rest, and a ? button explains every item.
  • Some new things, too. Weather Underground support, rounding for Home Assistant values, AM/PM as text, brightness down to 0%, and saving layouts straight onto the clock.

Now the details.

1. Why a robustness release?

Frixos runs on an ESP32 with no external RAM. Everything it does (the display, the scrolling text, the web page, Home Assistant, your CGM, the weather, the updates) shares a few hundred kilobytes, and only a few tens of those are free once everything is running.

Every secure (HTTPS) connection needs one unbroken block of roughly 17 KB just for its input buffer. When memory is tight, or chopped into small pieces, that block isn't there, and the connection fails. You'd have seen that as an integration dot turning amber, a gap in a graph, a weather icon that didn't update, or, rarely, a clock that needed a restart.

Adding features makes this harder, not easier. So before adding more, we went after the foundations: how much memory each part of the firmware really needs, how connections share what's left, and what happens in the busiest moments, like the first minute after a restart. That's what most of this release is about.

2. The memory diet

Benoit's memory work (PR #227) went through the firmware piece by piece, and we added measurements on top of it to size things exactly:

  • Measured, not guessed. Every background task gets its own block of memory for its work (its "stack"). Those were sized generously years ago. We measured the real peak use of each one on v72, added a safety margin, and gave back the rest. The clock can now also report each task's headroom, so we can keep an eye on it.
  • Buffers that grow only when needed. Secure connections now allocate their buffers as they need them, instead of reserving the maximum up front.
  • The update task only exists during an update. It used to sit in memory permanently, waiting. It's now created when an update starts and removed when it's done.
  • No more patchwork. The graph drawing area is now allocated once at its largest size, so changing a graph no longer leaves holes in memory. Serving the web page also uses less memory than before.
  • Smaller connection buffers. The Home Assistant, FreeStyle and Nightscout clients each reserved 4 KB receive and transmit buffers they didn't need. They now use the same lean sizes as the update downloader.
  • A rare memory bug, fixed. Under the right timing, one of the shared download buffers could be released while it was still in use. That one is gone too.

The result, on our own test clock with Home Assistant and FreeStyle Libre active: about 64 KB free after start-up on v73 against about 43 KB on v72, and the lowest point never dropped below 35 KB, where v72 regularly dipped to around 14 KB. That headroom is what keeps secure connections from failing when several things happen at once.

3. Connections that hold up

  • One secure connection at a time. All secure connections in the firmware now take turns behind a single lock, and one won't start unless there's a large enough block of memory for it. Instead of failing halfway through, it waits its turn. (Benoit Poirier, PR #224.) In v73 the time-zone lookup joined the queue as well.
  • One Home Assistant session per cycle. The clock used to set up a fresh secure connection for every entity it read. It now keeps one connection open for the whole cycle, so a dashboard with nine values spends far less time and memory on connection setup.
  • No more stuck connections. After a single network timeout, the FreeStyle Libre or Nightscout connection could get stuck and stay that way until the clock restarted. They now close and start fresh after any network error.
  • No interruptions mid-handshake. The display used to wake up every few milliseconds at a higher priority than the network, which slowed down every connection setup. It now sleeps until the next scroll step is actually due.
  • Better clues when something does fail. Connection errors now show up in the web log with the error code and the free memory at that moment, so a bug report tells us what actually happened.

4. A calmer first minute

The busiest moment in a clock's life is the minute after it restarts. Wi-Fi connects, the time is set, and then everything wants to go online at once: sunrise and weather, Home Assistant, your CGM, the update check. If you had the web page open when you restarted the clock, the page reloaded right in the middle of all that, asked for dozens of files, and chopped memory into pieces just as the clock needed big blocks for its connections. The result could be a clock that showed the time but no weather, glucose or Home Assistant values for a while.

v73 fixes this from both ends:

  • Connections wait for start-up. No secure connection starts until the clock has finished starting up. (Benoit Poirier, PR #227.)
  • The web page waits for the first round. The clock now opens its web page only after its first round of fetches has run, typically 20–25 seconds after Wi-Fi connects, and never more than a minute. (Setting up a brand-new clock is unchanged: its setup page is there straight away.)
  • The page counts down. When you restart the clock from the web page, after a firmware update or a setting that needs a restart, the page now shows a 60-second countdown and stays quiet until it's done, then reconnects by itself.
  • Weather doesn't give up too early. If the weather fetch has to skip a turn because memory is briefly short, it now tries again 30 seconds later, instead of counting it as a failure and pausing the weather for half an hour.

5. Bugs you could see, fixed

  • The clock that froze at dusk. A customer told us their clock's time sometimes stopped updating when the light sensor switched between day and night brightness. Two things combined: the switch restarted the clock/glucose alternation from scratch every time, and while the scrolling text was busy, the once-a-second work that updates the time could be put off again and again. The alternation now carries on across the switch, and the once-a-second work always gets its turn.
  • Home Assistant values that went blank. Saving a layout or a message could turn every Home Assistant value into "-" until the next scheduled refresh, which can be many minutes away. The values now stay put through a save, and fresh ones arrive within seconds.
  • The vanishing digit. Now and then the last digit of the time disappeared after a redraw. Deep in the graphics library, two digit images being decoded at the same moment could fight over a shared buffer, and the loser was simply skipped. The digit now stays put, and the clock does less redrawing to boot.
  • Smoother scrolling. The scrolling line now runs on a real-time clock instead of counting frames, so a busy moment elsewhere makes the text catch up instead of pausing. It only draws the characters you can actually see, and it gets priority over background work. If your layout ever stutters anyway, System → Danger zone → Scrolling line lets you switch to the graphics library's own animation.
  • Second digit themes after a restart. If your layout used a different digit theme for the second (aux) digit display, it now survives a restart.
  • No full-brightness flash at start-up. The clock now starts at your saved day or night brightness from the first moment, which matters most when it restarts at 3 a.m.
  • Schedules saved to the minute. Wi-Fi and dimming schedule windows set to anything other than a whole hour were quietly rejected. They now save exactly as you set them.

6. FreeStyle Libre: a much tougher client

LibreLinkUp can be fussy. Accounts are tied to regions, the service sometimes asks you to accept new terms, and too many failed logins can lock you out. Benoit rewrote the login flow to deal with all of it (PR #222), and refined it further in v73:

  • Region redirects are followed automatically. If your account lives on another regional server, the clock switches to it and retries.
  • Clear messages for each kind of rejection: wrong credentials, terms waiting to be accepted in the app, a temporary lockout, or an app version the service considers too old.
  • It backs off. After a rejected login the clock pauses instead of hammering the service, so a typo can't get your account locked. Since v73, a short network hiccup no longer triggers a fresh login either.
  • No more half-drawn graphs. The HTTP 400 errors that left gaps in the graph are gone, and if a history download fails partway, the clock now discards the partial data instead of drawing an incomplete curve.

7. A friendlier layout editor

The layout editor is for people who really want to make their screen their own. It's powerful, but it used to greet you with every possible item at once, including many that weren't on your screen at all. v73 tidies it up:

  • The palette shows what's on your screen. Only the items your layout actually uses are listed, so it doubles as a table of contents for your screen.
  • Add Item adds the rest. A new + Add Item tile opens a chooser with everything you can still add: another text line, a graph, an icon, the second digit display and more.
  • A "?" that explains. The new ? button next to the palette lists every item with its icon and two or three sentences on what it's for and how to use it.
  • Delete means delete. The old "Enabled" checkbox is replaced by a clear Delete button at the bottom of each item's settings.
  • Save to device. Give your layout a name and it's stored on the clock next to the built-in presets, ready to apply from the gallery.

Two smaller touches for the web page as a whole: it now reopens the tab you were on when you refresh it, and while it's fetching settings from the clock it shows a small "Retrieving settings…" note, so you're never looking at half-loaded values.

8. New things, too

  • Weather Underground. Bring a real personal weather station onto your clock, next to the met.no forecast. Enter an API key and any public station ID on the Integrations tab, and eight new tokens become available: [wu:temp], [wu:hum], [wu:dew], [wu:wind], [wu:gust], [wu:pressure], [wu:rain] and [wu:uv]. All eight come from a single fetch per cycle, because a second weather source shouldn't double the network traffic.
  • Rounding for Home Assistant values. Some sensors report far more decimals than you want on a wall. Add .N to the end of a token to round to N decimals: [HA:sensor.ground_power.0] shows a whole number, .1 one decimal, and so on.
  • AM/PM as text. In 12-hour mode, the AM/PM indicator can now show the letters AM/PM instead of a sun or moon. It now comes and goes with the main digit display, it's shown at its full height, and digit themes can ship their own AM/PM lettering to match.
  • Brightness down to 0%. Day and night brightness both accept 0, in the web page, the device API and the Home Assistant integration. If you want the projection completely dark at night, you can have exactly that.
  • Safe power limits per board. Revision 2 boards cap LED power at a safe drive level, and the System tab shows your board revision and its power cap side by side.

9. Under the hood

  • ESP-IDF 6.1 and LVGL 9.6. The firmware builds on the latest Espressif framework and graphics library, with their bug fixes and the on-demand connection buffers mentioned above.
  • Layouts and power-on hours moved to LittleFS. They moved off the small settings partition onto the new filesystem, so the settings can be safely wiped and rewritten if a clock ever needs rescuing.
  • Update checks that don't cry wolf. A failed "is there a new version?" check right after start-up no longer looks like a failed update. The clock waits for things to settle and retries first.
  • For tinkerers. If you flash your own web files onto the clock, an update no longer overwrites them (Benoit Poirier, PR #228). The settings and screen-layout HTTP API is now documented with examples.
  • Tests on every change. A check that compares the web page with the clock's settings runs automatically on every change, so a setting can't silently stop saving again.

Want your name in the next one? The firmware is open on GitHub, with a developer guide and an HTTP API reference. Bug reports, ideas and pull requests are all welcome.

How you get v73

Same as always: you don't have to do anything. Frixos checks for updates on its own, and every update arrives over the signed path that shipped in v67, verified on the clock before anything is written. The clock restarts on the new version. (If your clock is still on something older than v70, it does the one-time filesystem rebuild on the way.)

To check, open your clock's web page on your network and go to System. You'll see firmware 73 (version 2.80) there.

Here's to v73: not the longest feature list we've shipped, but the steadiest clock we've built. Hang it, set it, and forget about it.
